# v0.6.0 — Multi-provider publication workflow

## Summary

`tidal-parser` теперь принимает не только TIDAL links, но и Qobuz, Apple Music, Spotify, Yandex Music и manual metadata inputs, нормализует их в release identity и, где безопасно, доводит до TIDAL parser output.

## Highlights

- Qobuz / open.qobuz album links to TIDAL resolver
- Manual metadata resolver with release type selector
- Apple Music metadata extractor
- Spotify metadata extractor
- Yandex Music via Odesli bridge
- TIDAL candidates/scoring and strict safe handoff
- Copy-first publication workflow improvements

## User-facing changes

- Можно вставлять:
  - TIDAL URL
  - Qobuz canonical/open album URL
  - Apple Music album/song URL
  - Spotify album/track URL
  - Yandex Music track/album URL
  - manual line like `Artist — «Title» (Year)`
- Для manual input можно выбрать `Тип`: auto / album / ep / track.
- Для strong matches parser показывает ordinary TIDAL result.
- Для uncertain matches parser shows identity + candidates/scoring instead of forcing wrong result.

## Technical notes

- Apple/Spotify use direct HTML metadata extraction, no OAuth/headless/API.
- Yandex uses Odesli bridge only; no captcha bypass/direct HTML parser.
- Odesli `listen.tidal.com` links are normalized to `tidal.com`.
- Safe fallback paths avoid fabricated artist/title metadata.
- No new dependencies.

## Validation

- targeted tests passed during roadmap slices;
- live validation performed for:
  - Qobuz/open.qobuz;
  - manual album/track;
  - Apple Music;
  - Spotify;
  - Yandex track direct bridge;
  - Yandex album metadata fallback;
  - old TIDAL URL flow;
- Docker cleanup performed after rebuilds.

## Known limitations

- Apple `album?...i=<song_id>` stable track identity is a follow-up.
- Yandex/Odesli may rate-limit.
- Yandex album may not have direct TIDAL URL; metadata/candidates fallback is used.
- Strict handoff intentionally avoids uncertain auto-parsing.
