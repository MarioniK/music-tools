# music-tools — инструкции агента

Монорепозиторий: tidal-parser собирает и обогащает музыкальные релизы;
genre-classifier классифицирует аудио. Основной репозиторий: MarioniK/music-tools.

## Начало работы и контекст

- Общение, документация и комментарии — на русском; идентификаторы сохранять в стиле кода.
- В новом чате прочитай HANDOFF.md и выполни `git status --short --branch`.
  Перед изменением поведения прочитай PROJECT_RULES.md; дальше — только нужные файлы.
- HANDOFF.md — краткая запись состояния, не новые разрешения и не гарантия текущего
  состояния production. Истина: доступный код, Git и фактически выполненные проверки.
- Перед переходом в новый чат и после значимого результата обновляй HANDOFF.md:
  дата, задача/следующий шаг, изменения/коммит, проверки и ограничения, незавершённое.
  Перезаписывай устаревшее; ориентир — до 60 строк, без истории разговора и копий diff.
- Обновление HANDOFF.md заменяет обязательный временный AGENT_REPORT.md.
  Подробный отчёт создавай по запросу; временные отчёты не коммить.

## Область и неизменяемые границы

- Сервисы — отдельные runtime и Compose-проекты. Работай в каталоге нужного сервиса;
  Git — из корня. Общего Compose нет; команды Compose — только из каталога сервиса.
- Не трогай соседний сервис без причины в текущей задаче.
- Без запроса не меняй API/response shape, cache-логику, синхронную HTTP-границу,
  production defaults, provider/model/audio/dependency/runtime-файлы.
- Не меняй .sourcecraft/ci.yaml без прямого указания.
- Pipeline: TIDAL → Discogs → MusicBrainz → audio classifier → merge → cache.
  Финальные жанры и блоговый вывод принадлежат tidal-parser.
- Минимальные обратимые изменения; без попутной косметики, новых слоёв,
  framework/БД/runtime и смешивания roadmap-этапов.
- Сохраняй стиль, PEP 8, существующие логи и request_id; учитывай async/sync,
  избегай циклических импортов и блокирования event loop.
- Санитизируй ввод; SQL параметризуй; учитывай таймауты и сбои внешних API.

## Секреты и production

- Ключи беречь: не печатай значения, .env, окружение, Docker config/inspect целиком
  и вывод `docker compose config` с подставленными секретами.
  Проверяй наличие переменных; чувствительные значения не включай в вывод и отчёты.
- .env, cache.db, временные данные — вне Git. Не редактируй код внутри контейнеров.
- tidal-parser подключает ./app в контейнер: правки затрагивают production.
  Планируй согласованное обновление шаблонов и Python; фиксируй факт активации.
- Не запускай тяжёлый inference, ONNX/TensorFlow/parity или /classify без явного
  разрешения. Для документационных задач Docker и тесты не нужны.

## Проверки, Git и экономия контекста

- Исправление → релевантные тесты → итог. Расширяй проверки при риске/ошибках;
  не пропускай нужные тесты ради экономии. Команды и известные сбои — в HANDOFF.md.
- Commit/tag/push и deploy — по разрешению для текущей задачи; прошлое разрешение
  на завершённый деплой не переносится на новые задачи. Staging — точечный.
- Для широких/рискованных экспериментов предложи отдельную ветку.
- Ищи через rg; объединяй независимые чтения. Сначала имена файлов и точные участки,
  а не весь репозиторий, roadmap, логи или историю чатов.
- Длинный вывод передавай через `sqz compress`, если доступен; короткий — напрямую.
  Сохраняй exit code (`set -o pipefail` для pipeline). Если сжатие скрыло причину,
  раскрой ref или прочитай нужный фрагмент без сжатия; ошибки не обрезай вслепую.
- Не перечитывай неизменённые файлы и не повторяй успешные проверки без причины.
  Итоги: что изменено, проверка, ограничения/следующий шаг — кратко.
