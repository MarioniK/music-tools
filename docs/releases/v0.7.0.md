# music-tools v0.7.0

## Summary

`v0.7.0` is the general release summary for the Roadmap 6 security, quality, and release-readiness tranche.

The release closes the hardening work across both services without changing external contracts, response shapes, cache semantics, or provider/default logic.

## Included Changes

### Security and Dependency Hardening

- `tidal-parser`:
  - `lxml` upgraded
  - `requests` upgraded
  - FastAPI framework stack upgraded
- `genre-classifier`:
  - FastAPI / Starlette upgraded
  - `urllib3` upgraded

### Scanner Cleanup and Triage

- historical runtime evidence snapshots were removed;
- fresh scan context no longer produced Trivy SARIF after cleanup;
- residual Opengrep findings were triaged and classified as non-blocking or false positive;
- no blocking Opengrep findings remain in the current Roadmap 6 closure state.

### Env / Config Documentation

- service-scoped env examples were added:
  - `tidal-parser/.env.example`
  - `genre-classifier/.env.example`
- `.gitignore` was updated so those examples can be tracked while real local `.env` files remain ignored;
- `GENRE_PROVIDER=onnx_musicnn` is documented as the current `genre-classifier` example default;
- the release docs keep real secrets out of the repository.

### External API Resilience Audit

- `tidal-parser` external boundaries were reviewed in read-only mode:
  - TIDAL OpenAPI
  - Discogs
  - MusicBrainz
  - Odesli / Song.link
  - Qobuz
  - Apple Music
  - Spotify
  - internal audio-classifier HTTP boundary
- no obvious timeoutless network call was found;
- retry, circuit-breaker, and other future hardening ideas remain deferred because they can affect merge/cache behavior and should be treated as careful follow-up slices.

## Service Impact

### tidal-parser

- dependency hardening and scanner cleanup were completed;
- release-readiness documentation now covers env setup and the current external API resilience state;
- the service boundary, response shape, cache behavior, and resolver fallback behavior were not changed by this docs slice.

### genre-classifier

- the production example now reflects the current `onnx_musicnn` default;
- the release docs record the current rollback/fallback context without changing the runtime default itself;
- no `/classify` contract changes were introduced.

## Unchanged Contracts

- no external API response shape changes
- no cache semantics changes
- no provider/default logic changes
- no Docker/Compose changes in this release-docs slice
- `.sourcecraft/ci.yaml` remained unchanged after sync stabilization
