# v0.5.0 — ONNX default runtime release

## Summary

v0.5.0 фиксирует post-switch release state для `genre-classifier` после controlled ONNX default switch.

ONNX MusiCNN стал default runtime, default Docker target переключён на `onnx-runtime-slim`, а legacy MusicNN path сохранён как rollback/fallback context. Это release documentation for a runtime switch milestone, а не миграция `tidal-parser` и не изменение публичного response contract.

## Что изменилось

- default provider `genre-classifier` переключён на `onnx_musicnn`;
- default Docker target переключён на `onnx-runtime-slim`;
- ONNX runtime использует внешние артефакты из `/opt/music-tools-artifacts/genre-classifier/onnx`;
- legacy MusicNN path сохранён для rollback;
- release documentation и operator guidance собраны в постоянные docs.

## Что не изменилось

- `/classify` contract не менялся;
- response shape не менялся;
- `tidal-parser` code не менялся;
- legacy `.pb` model не удалялась;
- `essentia-tensorflow` dependency не удалялась;
- artifacts не коммитились в репозиторий.

## Validation

- controlled ONNX default switch completed successfully;
- full integration smoke passed: `tidal-parser -> genre-classifier` with ONNX default;
- provider logs confirmed `onnx_musicnn` and `OnnxMusiCNNProvider`;
- `file_processing_succeeded` was observed in logs;
- production observation showed a short CPU spike around 30%, not sustained 100%;
- container stayed stable and did not restart;
- current `genre-classifier` image footprint was observed around 1.57GB.

## Operational notes

- default runtime expects external ONNX artifacts to be present before startup;
- health check remains `curl http://localhost:8021/health`;
- integration smoke should still go through the real `tidal-parser` flow;
- operator logs should show the ONNX provider selection and successful file processing;
- TensorFlow/CUDA native warnings from Essentia dependencies are not blockers by themselves.

## Rollback notes

- rollback stays available through `genre-classifier-legacy`;
- legacy service/profile remains the fastest recovery path;
- rollback should restore `GENRE_PROVIDER=legacy_musicnn` and `legacy-runtime` target if needed.

## Migration notes

- this release does not include `tidal-parser` code migration;
- this release does not require response-parser changes from consumers;
- OpenVINO/iGPU is intentionally deferred to a future optional experiment.

## Known risks

- ONNX runtime depends on external artifact provisioning;
- one tested integration smoke does not replace future regression coverage;
- legacy rollback path must remain available until a later cleanup decision.
